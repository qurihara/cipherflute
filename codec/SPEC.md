# 符号の仕様

**別の言語で実装する人のための記述である。** 論文の設計章は読み物として書いてあるので、
ここでは実装に必要なことだけを、順を追って書く。

参照実装は2つある。`cipher_codec.py`（Python）と `../decoder/cipher_codec.js`（JavaScript）で、
どちらも同じ仕様を実装している。**書いたら `test_vectors.json` で突き合わせること。**

## 1. 音の高さの置き場（スロット）

音の高さを離散化した置き場を**スロット**と呼ぶ。

- 範囲は `lo_note` から `hi_note` まで。既定は **G#6 から G7** の12個
- 刻みは `step_cents`。既定は **100セント（半音）**
- 半音刻みにしてあるので、平均律の鍵盤楽器がそのまま対照表になる

スロット `i` の周波数は、`lo_note` の周波数に `i × step_cents` を足したものである。

```
freq(i) = freq(lo_note) × 2^(i × step_cents / 1200)
```

## 2. 基準笛

先頭に1本、**基準笛**を置く。既定は **C7**。

読み出しでは、まず基準笛の実測周波数を取り、以降のすべての音を**基準笛との比**で読む。
これにより、気温による伸縮も、吹く強さのくせも、まとめて打ち消せる。絶対音感も、
楽器が特定の調律であることも要らない。

```
残差(i) = 1200 × log2( (実測 / 基準の実測) / (スロットiの公称 / 基準の公称) )
```

残差が最も小さいスロットを選ぶ。残差が `decision_guard_cents`（既定は `step_cents / 2`）
を超えていれば、**読めなかった**として消失の印を付ける。

**基準笛はデータの音域の外に置いてもよい。** `use_reference=false` にすると基準笛を使わず、
絶対音程で読む（温度補正が効かなくなる）。

## 3. 隣接同音の禁止と差分符号化

`no_repeat=true` のとき、**隣り合う笛が同じ音にならない**ように符号化する。

理由は読み出しにある。同じ音が続くと、1本なのか2本なのかを音だけでは区別できない。
無音で区切る読み方でも、息が続いてしまえば同じことである。

実装は差分符号化による。記号 `d`（0 以上 `m-1` 未満、`m` はスロット数から1引いた数）を、
1つ前のスロット番号から `d + 1` だけ進んだ位置として書く。

```
slot[k] = (slot[k-1] + d[k] + 1) mod スロット数
```

起点は基準笛の公称スロットである。これにより、隣り合う笛は必ず違うスロットになる。

**1本あたりの情報量は log2(スロット数 − 1)。** 12スロットなら **log2(11) = 3.459 bit**。
隣接同音を禁じても、12スロットなら実質の損失はない。

## 4. 誤り訂正

Reed-Solomon 符号を使う。有限体の位数 `p` はスロット数から決まる素数である
（12スロットなら `m = 11`、位数11）。

- `ecc_parity` … 1ブロックあたりの検査記号の数。既定 **2**
- ブロックの長さは、記号の総数から自動で決める（`_block_layout`）
- **消失（どこが読めなかったか分かっている誤り）は、検査記号の数だけ訂正できる。**
  値の誤り（位置が分からない）は、その半分

読めなかった笛は**位置を詰めてはいけない**。詰めると以降の記号がすべてずれ、
本来なら直せる1本の欠落すら直せなくなる。**位置を保ったまま消失として渡す。**

## 5. 運ぶもの（mode）

- `mode="sequential"` … バイト列を運ぶ。`payload` が `bytes`
- `mode="symbols"` … 記号の列をそのまま運ぶ。小さな秘密や、人が読む番号に向く

## 6. 読み出しの手順（まとめ）

1. 音を1本ずつに切り分ける
2. 先頭を基準笛として、その実測周波数を取る
3. 以降の音を基準との比でスロットに丸める。丸められないものは消失にする
4. 差分符号化を解く（`no_repeat` のとき）
5. Reed-Solomon で訂正する
6. `mode` に応じてバイト列か記号列を取り出す

## 7. 秘密分散との組み合わせ

`threshold.py` に Shamir の秘密分散がある。k-of-n の断片を作り、各断片を1つの物体に載せる。

**実装上の注意。最高次の係数を 0 にしてはいけない。** k=2 で係数が0だと多項式が定数になり、
**すべての断片が秘密そのものになる**。`randrange(1, p)` を使うこと。

秘密分散を実装したら、**断片を並べて「全部同じ値の記号が無いか」を必ず見ること。**
これで気づける。

## 8. 試験ベクタ

`test_vectors.json` に12件ある。構造は次のとおり。

```json
{
  "config": { ... 符号の設定 ... },
  "vectors": [ { "payload": "...", "notes": ["C7", "G#6", ...] }, ... ]
}
```

各ベクタについて、`payload` を符号化すると `notes` になり、`notes` を復号すると
`payload` に戻ることを確かめる。

```bash
node ../decoder/cipher_codec.test.js     # ALL PASS (12 vectors)
python3 -c "import cipher_codec; print(cipher_codec.selftest())"
```

## 9. この仕様が守らないこと

**暗号学的な秘匿は一切無い。** 方式は公開で、秘密は値だけである。

- 音は公開のチャネルである。録音されれば読まれる
- 形状が秘密なので、3Dスキャンや写真測量で読まれうる
- 検査記号は事故（吹き損じ）を見つけるためのもので、**偽造を防ぐものではない**。
  仕様を知る者は、整合する偽物を作れる

秘匿が必要なら、秘密分散に一元化すること。復元した秘密そのものが自己検証的であること
（ハッシュが一致する、署名鍵として機能する）で、真正性を上の層に持たせる。
